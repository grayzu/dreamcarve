# Post-processors

Controllers read slightly different G-code. A **post-processor** is the
definition of one controller's dialect: how comments are written, what goes
at the start and end of a program, and how the spindle and tool changes are
handled. DreamCarve bundles two:

```text
grblhal  grblHAL
grbl     GRBL 1.1
```

(`dreamcarve posts` prints this list.)

Each project holds its own copy of the definition, in `post_processor`. A
DreamCarve upgrade never changes what an existing project exports.

## Choosing one

- `dreamcarve init part.svg --post grbl` creates a project with GRBL.
  grblHAL is the default.
- `dreamcarve export part.dcv --post grbl` switches an existing project to
  GRBL, saves the project with it, and exports. Your edits to the old copy,
  such as a longer spindle dwell, are replaced by the bundled values.

An unknown id is a usage error (exit code 2) that lists the known ones.

## What a program contains

For the coaster, with grblHAL:

| Part | Lines | Why |
| --- | --- | --- |
| Header | `( coaster )`, `( Generated by DreamCarve on … )`, `G90`, `G17`, `G94`, `G21`, `G54` | Absolute coordinates, XY plane, feed per minute, units, work coordinate system. A controller left in another state is corrected before any move. |
| Operation header | `( Operation 1: Profile )`, `( Tool 1: Set me )` | Comments for you. |
| Tool change | `M5`, `M0 ( Tool change: T1 Set me )` | Stop the spindle and pause so you can fit the tool. Resume with cycle start. |
| Spindle start | `M3 S18000`, `G4 P3.000` | Start the spindle clockwise at the tool's RPM, then wait 3 seconds for it to reach speed. |
| Motion | `G0`, `G1`, `G2`, `G3` | The toolpath. Rapids (`G0`) only at or above safe Z. |
| Footer | `M5`, `M30` | Stop the spindle; end the program. |

With automatic spindle control the program pauses with `M0` for every tool
change, the first one included, because neither controller changes a tool by itself: GRBL does not support
`M6`, and grblHAL's `M6` needs a sender that speaks its tool-change
protocol. Every pause is listed by `export`. With
[manual spindle control](#manual-spindle-control) the tool-change pause is
folded into the pause that asks you to turn the router on.

## grblHAL and GRBL compared

The motion is identical. Only these differ:

| | grblHAL | GRBL 1.1 |
| --- | --- | --- |
| Comments | `( text )` | `; text` |
| Tool change pause | `M0 ( Tool change: T1 … )` | `M0 ; Tool change: T1 …` |
| Messages | Shows `(MSG, text)` comments to the sender as `[MSG:text]` | Has no messages: comments are removed before the line is run |

## Units

`display_units` in the project chooses the program's units: `"mm"` writes
`G21` and millimetres, `"inch"` writes `G20` and inches (feeds in inches per
minute). Choose it with `init --units inch`, or change it in the file. The
project's own values stay in millimetres.

## Settings you may change

Most of the definition should stay as bundled. These are the fields worth
knowing:

| Field | Meaning |
| --- | --- |
| `file_extension` | The program's extension, without the dot. 1 to 8 letters or digits, and not `dcv`. Default `nc`. |
| `feed_speed.spindle_on_dwell.duration_s` | Seconds to wait after the spindle starts. Default 3. Raise it if your spindle or VFD takes longer to reach speed; 0 means no wait. |
| `feed_speed.spindle_control` | `"automatic"` (default) or `"manual"`. See below. |
| `number_format.decimal_places` | Digits after the point: `mm` at least 2, `inch` at least 3. Default 3 and 4. |

Names that DreamCarve puts in comments (the project, tool and operation
names) are reduced to plain ASCII without `( ) ; ! ? ~`. Both controllers
act on `!`, `?` and `~` immediately, even inside a comment, and `)` would
end a comment early.

## Manual spindle control

Many hobby machines use a trim router that you switch on and off by hand
rather than a spindle the controller starts. For those, set:

```json
"spindle_control": "manual",
```

in `post_processor.feed_speed`. The program then sends no `M3`, `M5` or `S`
word, no spin-up wait, and no separate tool-change pause. Instead it stops
once per tool before it cuts, and once after:

- Before each tool's first cut, it rises to safe Z and pauses:

  ```text
  G0 Z5.000
  M0 (MSG, Fit T1 Set me. Turn the router ON. Speed 18000 RPM. Resume to start cutting.)
  ```

  Fit the tool, switch the router on, set its dial to the speed shown, wait
  until it is at speed, then resume with cycle start. Without an `rpm` on
  the tool the message leaves out the speed. With manual control `rpm` is
  optional; the feed and plunge rates are still required. The `Fit …` part
  appears when the post-processor's tool change has a pause, as both
  bundled ones do. A long tool name is shortened so the message stays
  within 96 characters; the router instruction is never cut.
- After the tool's last cut, it rises to safe Z and pauses:

  ```text
  M0 (MSG, Turn the router OFF.)
  ```

  Switch the router off and resume. After the last tool the program then
  ends. Before a second tool, the program rises to safe Z again and stops
  with `Fit T2 … Turn the router ON. …` for the next tool.

For the coaster, the program pauses twice: to fit the bit and turn the
router on, and to turn it off. `export` lists each pause with its line
number:

```text
Pauses (M0); resume each with cycle start:
  line 11: Fit T1 Set me. Turn the router ON. Speed 18000 RPM. Resume to start cutting.
  line 993: Turn the router OFF.
```

### What the controller does with the pause

From the GRBL and grblHAL source code:

- **The pause is reliable on both.** `M0` waits until every earlier move has
  finished, then holds. The machine resumes only on cycle start (`~`, or
  your sender's Resume or Start button).
- **The message is not.** GRBL does not support messages: it removes
  comments before running a line, so it never shows the text. grblHAL sends
  a `(MSG, text)` comment to the sender as `[MSG:text]`.
- Whether your sender shows that message is not yet checked on real
  senders. Do not rely on it. Use the pause list `export` prints, or read
  the line your sender stopped on.

The router is switched by hand, so DreamCarve cannot check that it is
running. Never resume a "Turn the router ON" pause until it is running at
speed.

## Not yet checked on a real machine

The bundled definitions were checked against the GRBL and grblHAL source and
documentation, not yet on a running machine. Before your first cut, check
on your controller:

- Laser mode is off (`$32=0`). Laser mode is for lasers and changes how the
  controller treats spindle commands.
- The maximum spindle speed (`$30`) is at or above the RPM you set, or the
  spindle runs slower than asked.
- The spin-up wait is long enough for your spindle.
- Your sender shows comments and pauses the way you expect.

The sources are listed in the repository, in
`crates/dc-gcode/src/definitions/README.md`.
