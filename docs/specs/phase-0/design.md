# Phase 0: Scaffold — Design Spec

**Status:** accepted
**Functional spec:** `functional.md`

## Overview

Phase 0 lays down the workspace, the quality gates, the release pipeline, the
docs site, and the parity tooling. All of it is configuration and glue; the
only Rust is a hello-world CLI, empty library crates with doc comments, and
the header checker.

## PureCutCNC sources

| DreamCarve | PureCutCNC | Notes |
| --- | --- | --- |
| `tools/check-headers` | `scripts/check-license-headers.ts` | Reimplemented in Rust as a tiny bin crate so CI needs no Node. Accepts either header form from `AGENTS.md`. |
| `tools/parity/` | `src/engine/toolpaths/parityCorpus.ts`, `parityRecord.ts` | TypeScript, run with Node against a local checkout. `canonicalize` (key-sorted JSON) is reused for stable goldens. |

## Workspace layout

```
Cargo.toml                 # [workspace], shared lints, shared dependency versions
crates/
  dc-geometry/             # points, polylines with arcs, transforms, offsets, flattening
  dc-project/              # Project data model, serde, versioning, migrations
  dc-cam/                  # toolpath generators (phase 1: Profile)
  dc-gcode/                # post-processor model and emission
  dc-import/               # SVG (phase 1), DXF (phase 2)
  dreamcarve/              # the CLI binary
tools/
  check-headers/           # bin crate, run in CI
  parity/                  # Node script + README, not part of the workspace
tests/
  golden/                  # committed PureCutCNC outputs, read by cargo test
docs/
  book/                    # mdBook
  specs/ adr/ agents/ plan.md
```

Crate names carry a `dc-` prefix so they do not collide on crates.io if ever
published. The binary crate is `dreamcarve`.

Workspace `Cargo.toml` sets `edition = "2024"`, `rust-version` to the current
stable, the `[workspace.lints]` table listed in `docs/rust-guidelines.md`
("Toolchain and workspace": `unsafe_code = "forbid"`, unwrap/expect/panic
denied for library crates, allowed in tests and the CLI with a comment), and
`[workspace.dependencies]` for serde, serde_json, thiserror, and the geometry
crates so versions are set once. A `deny.toml` for `cargo-deny` lists the
allowed licenses from the same guide; CI runs `cargo deny check licenses
advisories`.

## CI

`.github/workflows/ci.yml`: matrix over `ubuntu-latest`, `macos-latest`,
`windows-latest`. Steps: checkout, install stable with `rustfmt` and `clippy`,
cache, `cargo fmt --all -- --check`, `cargo clippy --all-targets
--all-features -- -D warnings`, `cargo test --all`, `cargo run -p
check-headers`, `cargo deny check licenses advisories`. Docs job: install mdBook, `mdbook build docs/book`, `cargo doc
--no-deps --workspace`; on `main`, deploy both to Pages under `/` and
`/api/`.

`.github/workflows/release.yml`: generated by `cargo dist init`, triggered on
`v*` tags, targets `x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`,
`x86_64-apple-darwin`, `x86_64-pc-windows-msvc`. Unsigned in phase 0; signing
is phase 9.

  `needs-triage`.
- `.github/ISSUE_TEMPLATE/bug.yml`: Steps, Expected, Actual, Project file
  attached, Controller.
- `.github/ISSUE_TEMPLATE/phase-spec.yml`: links the spec PR.
- `.github/pull_request_template.md`: checklist: tests from the issue land
  first; headers correct; safety assertions present if machine output
  changed; docs updated; `CONTEXT.md` updated if a term changed.

## Parity tool

`tools/parity/capture.ts`, run as `npx tsx capture.ts --purecutcnc
../purecutcnc --case <name>`. It imports `computeOperationToolpath` and
`runPostProcessor` from the checkout, loads `cases/<name>.camj`, writes
`tests/golden/<name>/program.nc`, `toolpath.json` (canonicalized), and
`README.md` describing the case, its tolerance, and the PureCutCNC commit it
was captured from. Phase 0 ships one smoke case: a rectangle Edge Route with
no tabs, grblHAL.

## Test plan

Phase 0's behavioural tests are the acceptance tests in the functional spec,
exercised by CI itself, plus the header checker's own:

- `check_headers::accepts_dreamcarve_header` — a file with the DreamCarve
  header passes.
- `check_headers::accepts_upstream_header` — a file with the PureCutCNC
  attribution header passes.
- `check_headers::rejects_missing_header` — a file with neither fails and the
  message names the path.
- `check_headers::skips_generated_and_target` — `target/` and files marked
  `@generated` are ignored.
