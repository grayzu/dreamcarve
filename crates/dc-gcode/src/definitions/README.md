# Bundled post-processor definitions

`grblhal.json` and `grbl.json` come from PureCutCNC
(<https://github.com/PureCutCNC/purecutcnc>), Copyright 2026 Franja (Frank)
Povazanj, licensed under the Apache License, Version 2.0. See the repository
`NOTICE`.

Upstream paths, at commit `2ebab10e5e17c48281ff96805d5e936af135cb58`:

- `src/engine/gcode/definitions/grblhal.json`
- `src/engine/gcode/definitions/grbl.json`

## Modifications

These files were modified from the upstream copies (Apache-2.0 §4(b)):

- Keys are converted from camelCase to snake_case (`fileExtension` →
  `file_extension`, `spindleOnCW` → `spindle_on_cw`), because DreamCarve
  embeds a copy of the definition in every `.dcv` file and `.dcv` keys are
  snake_case (`docs/rust-guidelines.md`, "Serialization").
- `"vendor": null` is added, since every field is required and `Option`
  fields are written as `null`.
- The header line `Generated by PureCutCNC on {date}` reads
  `Generated by DreamCarve on {date}`.
- The safety and correctness changes listed under "Verification" below.

Values are otherwise unchanged. `{placeholder}` tokens such as
`{programName}` and `{date}` are template tokens filled at export, not keys,
so they keep their upstream spelling.

The schema is `dc_project::PostProcessor`. The test
`post::tests::bundled_definitions_validate` checks that both files parse.

## Verification

Checked on 2026-10-15 against each controller's own source and wiki
(`AGENTS.md`, "Reference implementation"), then against the phase 1 safety
rules S1–S6. The `post::tests` in `dc-gcode` lock each finding in.

| Change | Both / file | Why |
| --- | --- | --- |
| `work_coordinates.select_command` `null` → `"G54"` | `grbl.json` | S5. GRBL supports G54–G59; a program that never selects a WCS runs in whatever one the controller was left in. |
| `G94` added to the header | both | Units-per-minute feed. Both controllers support G93 inverse time, which changes what `F` means if left active by an aborted program. |
| Footer `[]` → `["M5"]` | `grbl.json` | S4 says the footer stops the spindle. M30 also does, but S4 is checked on the text. |
| Footer `G0 G53 Z0` removed | `grblhal.json` | With soft limits on, machine Z0 is outside the envelope (max is −pull-off) and raises an alarm; unhomed, machine Z0 is wherever Z was at power-on. The program already ends at safe Z. |
| Tool change `M6 …` → `M0 ( Tool change: T{toolNumber} {toolName} )`, `pause_after_change` → `false` | `grblhal.json` | M6 without a T word is ignored; with one, it needs a sender that speaks grblHAL's tool-change protocol (`$341`). M0 after M5 pauses on every setup. |
| Tool change pauses once, `pause_after_change` → `false` | `grbl.json` | The command list already has M0, so `true` made the operator press cycle start twice. GRBL does not support M6. |
| `{operationDescription}` lines removed | both | `emit` does not fill that placeholder, so it would reach the machine as literal text. |
| Em-dashes in `description` → `-` | both | Bytes above 0x7F are real-time commands on both controllers (0x94 is a feed override). |

Rules for the emitter that come from the same check (enforced in `emit`, not
here): text substituted into comments (`{programName}`, `{toolName}`,
`{operationName}`) is reduced to printable ASCII without `( ) ; ! ? ~`,
since both controllers act on `!`, `~`, `?` and bytes above 0x7F even inside
comments, and `)` ends a comment early. Never emit M4 (needs a direction pin
or laser capability) or M7 (optional on both). Numbers never use exponent
notation. Arc IJ offsets are taken from the rounded start point emitted.
